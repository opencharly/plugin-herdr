# 2026.245.0926 — fix: pane-wait-output without a pane — resolve the focused pane first

## Summary

Two changes:

1. **fix (the check-herdr-pod finding):** `herdr: pane-wait-output` with no
   `pane` (the focused-pane default) hit `recv: EOF` — the herdr wire schema
   REQUIRES `pane_id` on `pane.wait_for_output`. The engine resolves the
   server's focused pane via `pane.current` first, then waits with the
   resolved id. The verb's resolved dispatch now dials the resolver's address
   as-is (bare host:port → tcp implied; unix:// targets work directly).
2. **test: live-only, fakes deleted.** The fake-socket NDJSON test server was
   the wrong tool — charly's acceptance gate is the live bed, and the fake
   drifted from reality (claimed `workspace.create` returns w2; the real
   server returns w1; the fake missed the one-request-per-connection contract
   — the live container probe caught both). Tests now run against the REAL
   session: engine + verb dispatch read-only surfaces, and the focused-pane
   B12 test (real `pane.current`, wait with an empty pane id on the real
   pane's real output). Mutating surfaces remain the check-herdr-pod bed's job.
